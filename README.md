# 成绩分析工作区 · 使用说明

## 目录怎么放

```
成绩分析工作区/
├─ 脚本/                  ← 代码，放着别动
│   ├─ 工作区路径.py         规定「代码在这、数据在 数据/」——路径都从这取
│   ├─ 按班拆分成绩.py
│   ├─ 生成分析页面.py
│   ├─ 页面模板.html
│   ├─ 生成科任老师文档.py   给科任老师的单科文档（见下）
│   ├─ 科任老师模板.html
│   ├─ 验证科任文档.py       用无头浏览器核对生成结果
│   └─ 导出图片.py           把 html 整页转成 png（见下）
│
├─ 数据/                  ← 所有成绩数据都在这，与代码分开放
│   └─ 九年级9月考/         每场考试一个目录，名字自己取
│       ├─ 九年级9月考.xlsx 原始成绩表，直接丢进来
│       ├─ 配置.json        （可选）表格格式特殊时才需要，见下
│       ├─ 分班数据/        脚本生成：每班一份 CSV
│       ├─ 九年级9月考.html 脚本生成：分析报告
│       ├─ 总结.json        （可选）手写的考试情况总结，见下
│       └─ 科任老师文档/     脚本生成：每科一份，给科任老师
│           ├─ 11班-语文.html
│           └─ 11班-语文.png 转出来的图片，发给科任老师用
│
└─ README.md              本文件
```

**代码与数据是分开的**：仓库（版本管理）只管 `脚本/` 与文档，`数据/` 整个不纳入，
连 `配置.json`、`总结.json` 也不进——所以仓库里一个字节的学生成绩都没有。

**引入新考试**：在 `数据/` 下新建一个目录（名字就是考试名）→ 把 xlsx 丢进去 → 跑下面两步。

## 怎么跑

在本文件夹下打开 PowerShell，`$py` 指 Python（本机没加进 PATH，用完整路径）：

```powershell
$py = "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe"

& $py 脚本\按班拆分成绩.py 九年级9月考      # 第一步：拆成每班一份 CSV
& $py 脚本\生成分析页面.py 九年级9月考      # 第二步：生成 HTML 报告
```

两步分开跑是故意的——每步的输出都能先核对，出问题好定位。

跑完打开 `九年级9月考\九年级9月考.html` 看报告。数据改了重跑第二步即可。

## 结果怎么看

拆分脚本会打印每班人数，**先看这几个数字**：

- 各班人数是否和花名册对得上（一般 40 人上下）
- 有没有「未分班」——有就说明学号列或学号格式和预期不一样
- 有没有「预期外的班别编号」——有就说明班别位次取错了

分析脚本会打印等级→年级排名区间和班级概览自检。**关键一条：全年级各档计数合计必须等于全年级人数**。
不相等就说明等级集合漏了档位（这个坑踩过：等级是 A~T 共 20 档，不是 A~R 的 18 档，
少算两档会静默丢掉 37 个人）。

## 表格格式不一样怎么办

历史表格可能不一致，**不要直接改脚本**。直接告诉 Claude「用 grade-analysis 分析这个表」，
它会先探查表格结构（工作表名、表头行、列分组、学号样式、等级取值），核对完再决定要不要写配置文件。

探查用的工具在 `.agents/skills/grade-analysis/scripts/探查工作簿.py`，也可以自己跑：

```powershell
& $py .agents\skills\grade-analysis\scripts\探查工作簿.py 新考试\新考试.xlsx
```

### 配置.json

只有默认值不适用时才需要建。放在考试目录下，按需写几项即可：

```json
{
  "工作表": "成绩分析",        // 数据在哪张工作表
  "表头行": 1,                 // 表头在第几行
  "数据起始行": 2,             // 第一条学生记录在第几行
  "学号列": 1,                 // 学号在第几列（A=1）
  "班别位起": 6,               // 学号里班别从第几位开始
  "班别位数": 2,
  "保留列数": 26,              // 只取前 N 列
  "重点班级": ["01", "02", "11"],   // 报告里重点对比哪几个班
  "等级顺序": null,            // 等级不是字母时才需要写顺序
  "排名基准科目": "总分"        // 等级→排名区间从哪一科推导
}
```

行号列号都从 **1** 开始数，和 Excel 里看到的一致。

## 已知的坑（都踩过，换表时逐项核对）

| 事项 | 实际情况 |
|---|---|
| 学号的班别位次 | 第 **6~7** 位（`032420102` 的 `01`）。不是第 5~6 位 |
| 等级体系 | **两套**：九年级是 A~T 共 20 档（按年级排名，每档 25 人）；七八年级是 A+/A/B+/B/C+/C 六档 |
| 等级排序 | **不能按字母排** —— 字母序会把 `A+` 排到 `A` 之后，但 A+ 其实更好。配置里已显式写顺序 |
| 「每三列一组」 | **并非普遍成立**。八年级上/下的「体育」只有一列，从该处起分组整体错位。识别改用扫描式：表头文字 + 排名 + 等第 才算一组 |
| 保留列数 | 各表不同（**26/30/32/35/36**），且可能超过 A~Z。拆分脚本会自动检查：若截断处之外还有完整科目组，直接报错并告知应改成多少，不会默默切掉 |
| 八年级下前两列 | **顺序相反**：A=姓名、B=学号。不改配置会按姓名分班，全员落进「未分班」 |
| 表尾空行 | 末尾有成片空公式行，脚本会自动跳过 |
| AA~AC 列 | 九年级表里是「等级起止排名对照表」图例，不是数据，**不取** |
| 化学 | 满分仅 10 分且大量同分，与其他科目不可横向比较，报告里会单独标注 |
| 分档数 | 等级 ≥ 8 档分四组（优秀/良好/中等/待提高），< 8 档分三组（优秀/中等/待提高） |

## 总分口径：各年级统一

七八年级另有「加体育权重总分」「不加体育权重总分」，且七年级上根本没有「总分」。
脚本**一律取「不加体育权重总分」并改名为「总分」**，使各年级报告的「总分」含义一致
（九年级无体育列，其「总分」本身就不含体育）。
「加体育权重总分」作为独立科目保留，不参与「总分」口径。

## 报告里有什么

1. **班级总览** — 总分均分、优秀率等关键指标卡，对照全年级基准
2. **单科跨班深度对比 · 分数分布与等级构成** — 选一个科目，看各班分数分布曲线比位置高低和胖瘦；
   **背后的灰色分带就是该科的等级分界**，带顶字母为档位；鼠标悬停可同时看到「所在分数段人数」和「所在档位人数」
3. **科目 × 等级人数热力图** + **各科等级分布曲线** — 上面是逐档人数，下面把同一批数据画成平滑的密度曲线，
   一科一条，便于比较各科的分布形状；鼠标移到图例上可单独高亮某一科。
   曲线由该科**原始分数**做核密度估计后映射到各档而来，纵轴按各科自身归一化，
   **峰高不等于人数占比**，确切人数看上面的热力图或浮窗
4. **明细数据表** — 可排序，可导出 CSV

第 3、4 节的班级默认都是 **11 班**。

页面右上角可切换浅色/深色（默认跟随系统），适合投屏或打印。

### 本班在图上永远是橙红加粗的那条

主报告和科任文档都这样：**本班（11 班）固定用橙红色 `#eb6834`，线也画得更粗**，
一眼就能在几条曲线里找到自己班。

这个橙红**原来分配给 2 班**，现在被本班占用，2 班换成了绿色、1 班仍是蓝色。
配色集合没变，只是哪个班用哪个色变了，所以原来通过的颜色区分度检验依然成立。

哪个班算「本班」由 `配置.json` 里的 `本班` 项决定，默认 `"11"`。
它必须同时出现在 `重点班级` 里（科任文档会自动补上，主报告只提示不补）。

## 给科任老师的单科文档

每位科任老师只看自己那一科，所以按科目拆成独立文档，每份三节（顺序固定）：

1. **本次大考** · 该科 —— 开头一段**考试情况总结**（140 字内，讲整体形态，
   专挑均分看不出、曲线上才明显的问题：双峰、低分孤点、重心偏下等），
   然后是各班分数分布曲线 + 等级构成
2. **本班该科目标生** —— 谁的总排名靠前但这一科掉队。
   **默认按总排名由前到后排列，点任意列头可换排序**（再点一次反向）。
   年级总排名前 10 的行用**浅琥珀底**标出——这批学生整体非常拔尖，该科是他们的相对短板，
   补上见效最快，与其余学生不是一回事。
3. **上次大考** · 该科 —— 同第 1 节的结构（历史对比放最后，科任老师最关心本次）

**等级构成分两块**：上块是该科、下块是总分。这样一眼能判断是不是偏科——
该科靠后、总分也靠后，是整体问题；该科靠后而总分不靠后，才是这一科的真短板。

**曲线图下方有读图说明**，讲的是这套统计方式（核密度估计：不假设正态、不预设分数线，
峰位与胖瘦都是数据本身的样子）以及怎么看图（峰的位置、峰的胖瘦、两侧的尾巴）。
科任老师不是教统计的，这几句话比坐标轴上的数字有用。

### 考试情况总结可以自己写

每份文档开头那段总结，**默认优先用你手写的版本**：在考试目录下放一个 `总结.json`，
按科目给文字（140 字以内）即可，没有写的科目才用脚本自动生成的初稿。

```json
{
  "数学": "三条曲线里最摊的一条。均分只落后 1.4 分，但两头都松……"
}
```

为什么留这个口子：这段话的价值在于**看图之后的判断**，脚本套模板只能给个初稿。
建议的用法是——先跑一次生成脚本，打开文档看一眼曲线，再把你要说的话写进 `总结.json`，
重跑一次即可。验证脚本会核对文档里用的是不是你写的那一版，写错了会提示。

```powershell
& $py 脚本\生成科任老师文档.py 九年级9月考 八年级下 --班级 11
& $py 脚本\验证科任文档.py
```

第一个参数是本次大考、第二个是上次大考（两场都要有，才能做对比）。输出在
`九年级9月考\科任老师文档\11班-语文.html` 这样，一科一份。

**科目**默认取两场考试的交集，再排掉化学、总分——化学满分 10 分且大量同分、排名不具筛选意义，
「总分排名落后于总排名」则自相矛盾。本次实际出 6 份：语文、数学、英语、物理、历史、思政。

**目标生口径**：年级总排名前 100，且该科排名 > 总排名 × 1.3。用的是**去英才班**的 487 人排名基数
（与工作区既有报告一致，不是含英才班的 516 人版）。

**两次考试的等级档位不同**（八下是 A+~C 六档，九年级是 A~T 二十档），所以两节分开布置、
各画各的档位，**不要跨节比同一个字母**。

第二个命令会用无头浏览器把文档真渲染一遍再核对（图形全是 JS 画的，光看源码看不出问题），
会检查档位字母是否齐全、表格行列数、目标生姓名是否都在。**这一步别跳过。**

完整流程文档见 `.agents/skills/subject-teacher-report/SKILL.md`（同类：成绩表处理见
`.agents/skills/grade-analysis/SKILL.md`）。工作区入口是 `AGENTS.md`。

### 转成图片（发给科任老师）

```powershell
& $py 脚本\导出图片.py 九年级9月考\科任老师文档
```

把该目录下每个 html 整页转成一张 PNG，**与 html 同目录、同名**（`11班-语文.html` →
`11班-语文.png`），直接拖进微信/钉钉发给科任老师即可。本次 6 张各约 400 KB、1400×3200~3555 px。

`--缩放 2` 可出更清晰的版本（适合打印，文件约大一倍）。同一脚本也能转主报告：
`& $py 脚本\导出图片.py 九年级9月考`。
