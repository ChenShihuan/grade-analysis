# 成绩表分析

处理「成绩分析工作区」下的考试成绩数据：拆分班级 → 统计等级 → 生成 HTML 报告。

**核心原则：先探查，再配置，最后跑脚本。** 绝不能拿默认配置直接跑——表格格式历史上有过不一致，
解析假设一旦不成立会**静默出错**（分错班、丢学生），而不是报错。

## 工作区结构

```
成绩分析工作区/
├─ .agents/                           ← 通用 agent 协议目录（见 .agents/README.md）
│   └─ skills/grade-analysis/
│       ├─ SKILL.md                    ← 本文件
│       └─ scripts/探查工作簿.py
├─ 脚本/
│   ├─ 按班拆分成绩.py    xlsx → 各班 CSV
│   ├─ 生成分析页面.py    CSV → HTML 报告
│   └─ 页面模板.html      报告模板（含 /*__DATA__*/null 与 __EXAM__ 两个占位符）
└─ <考试名>/                          每场考试一个目录
    ├─ <考试名>.xlsx                  原始成绩表
    ├─ 配置.json                      （可选）结构参数，格式不符时才写
    ├─ 分班数据/*.csv                 脚本生成
    └─ <考试名>.html                  脚本生成
```

## 流程

### 1. 定位

确认考试目录名；目录里应有且只有一个 xlsx。有多个则需在 `配置.json` 里用「源文件」指定。

Python 解释器：`$env:LOCALAPPDATA\Programs\Python\Python312\python.exe`（本机未加入 PATH）。

### 2. 探查（不可跳过）

```powershell
& $py .agents\skills\grade-analysis\scripts\探查工作簿.py "<考试目录>\<考试名>.xlsx"          # 列出全部工作表
& $py .agents\skills\grade-analysis\scripts\探查工作簿.py "<考试目录>\<考试名>.xlsx" "成绩分析"  # 深入探查某表
```

输出会给出：表头行、列分组（每三列一组：分数/排名/等第）、学号样式与班别位次候选、各等第列取值集合。
**逐项核对下面的「已知口径」**，任何一项对不上就写进 `配置.json`。

### 3. 写 配置.json（仅在默认值不适用时）

放在考试目录下。两块配置合在一个文件里，两脚本都读它：

```json
{
  "工作表": "成绩分析",
  "表头行": 1,
  "数据起始行": 2,
  "学号列": 1,
  "班别位起": 6,
  "班别位数": 2,
  "保留列数": 26,
  "重点班级": ["01", "02", "11"],
  "等级顺序": null,
  "排名基准科目": "总分"
}
```

行号列号均从 1 开始，与 Excel 一致。「重点班级」是分析脚本用的，其余是拆分脚本用的。
不改的键可以不写。**不要写脚本不认识的键**（脚本会提示，但没用）。

- `等级顺序`：默认按字母排序。等级不是字母时（如 优秀/良好/中等）**必须**显式写顺序。
- `排名基准科目`：等级→年级排名区间从该科的排名列推导。非「总分」则改写。
- `保留列数`：只保留前 N 列。若表里成绩列更多，按实际改大。

### 4. 跑脚本

```powershell
cd "成绩分析工作区"
& $py 脚本\按班拆分成绩.py 九年级9月考
& $py 脚本\生成分析页面.py 九年级9月考
```

两步分开跑，每步都有输出可核对；不要写成一键脚本。

### 拆分脚本的截断防线

拆分脚本会检查：**在被截断的范围之外若还存在完整科目组**（表头文字 + 排名 + 等第），
就直接报错并给出应改成的列数，不会默默切掉。各年级表列数已见 26/30/32/35/36 五种，
有的还会超过 A~Z，所以这道防线是必需的。

注意它**不能**用「表头非空单元格数」判断——九年级表在数据列之后摆了「等级起止排名对照表」图例，
其表头行也带文字，会被误判成数据列。

### 配置文件容错

`配置.json` 一律用 `utf-8-sig` 读取：记事本 / PowerShell 保存的 UTF-8 会带 BOM，
普通 `utf-8` 读取会抛 `JSONDecodeError`。JSON 语法错误也会给出可读提示，不打印 traceback。

### 5. 自检（每次都做，输出里已打印，但必须自己读）

| 检查项 | 期望 | 不符说明 |
|---|---|---|
| 各班人数 | 与花名册一致，40 人上下 | 差太多 → 班别位次错了 |
| 出现预期外的班别编号 | 无 | 脚本会 ⚠ 提示 → `班别位起/班别位数` 错 |
| 未分班人数 | 0 | 脚本会 ⚠ 提示 → 学号列或学号格式与假设不符 |
| **全年级各档计数合计 == 全年级人数** | 相等 | **不等 → 等级集合漏了档位（见下）** |
| 四档占比之和 | 100% | 不等于 100% → 同上，或有学生没有等级 |
| 等级→排名区间 | 连续、无空洞 | 有空洞 → 排名列有问题 |

### 6. 报告

生成后**务必用浏览器渲染看一眼**（headless 截图即可），确认各节都渲染出来了。
若第 3 节之后的图表全空白，多半是 JS 抛错中断——用 `node --check` 检查抽出的 script，
但注意语法正确 ≠ 运行时正确（调用未定义的函数是运行时错误）。

## 已知口径与陷阱

这些是踩过的坑，默认值即按此设定：

| 项 | 实际情况 | 踩过的坑 |
|---|---|---|
| **学号班别位次** | 第 **6~7** 位（`032420102` 的 `01`） | 曾被描述为「第 5~6 位」，按此切分不报错但分成 20/21 班 |
| **等级体系** | **A~T 共 20 档**，非 A~R 的 18 档 | 按 A~R 统计会**静默丢弃 37 人**（S 25 人 + T 12 人），全年级占比之和只有 92.5% |
| **等级含义** | 按**年级排名**分档，与分数无关；A=年级 1~25 名，往后每档 25 人 | 数学 A 档分数横跨 79~95 分——是那 25 人进了年级前 25 名，不是都考了高分 |
| **等级区间** | 从「排名基准科目」的排名列**实际推导**，不假定每档 25 人 | 末档 T 只有 12 人 |
| **表尾空行** | 末尾有成片的空公式行（学号姓名为空） | 不跳过会输出一个假的「未分班」班 |
| **学号类型** | 可能是数字型（`32421062`） | 需 `zfill(9)` 补前导零，否则切错位 |
| **化学等科目** | 满分仅 10 分、分数高度并列（62% 学生同为 10 分） | 平滑分布曲线会造出假峰，占比也会失真；页面已自动标注 |
| **03~10 班** | 是低分集中班，与 01/02/11 差异极大 | 用全年级区间画分布曲线会把重点班压成右侧一小条 |
| **AA~AC 列** | 是**等级定义图例**，不是数据：AB 列 = `26,51,76,101…`，AC 列 = `B,C,D,E,F…`，表头行接着 `1,A`，合起来即「1→A、26→B、51→C…」的等级起止排名对照表 | 探查会把它误报为第 9 个科目组。它没有学号也没有分数；**保留前 26 列（A~Z）即可**，不要改成 55 列 |

**关于「保留列数」**：该表 `max_column` 报 57，但第 30 列起全空，27~29 列是上表的图例。
默认 26（A~Z）正确。若探查显示某考试确实有第 9 个科目，再按 `3 × 科目数 + 2` 调大。

## 各表实际差异（务必逐表核对，不要套用上一张的配置）

已核对的五张表，**没有两张完全相同**：

| 表 | 科目组 | 保留列数 | 等级体系 | 学号列 | 人数 |
|---|---|---|---|---|---|
| 七年级上 | 10 | 32 | A+/A/B+/B/C+/C 六档 | A(1) | 571 |
| 七年级下 | 11 | 35 | 同上 | A(1) | 564 |
| 八年级上 | 11 | **36** | 同上 | A(1) | 552 |
| 八年级下 | 9 | **30** | 同上 | **B(2)** | 541 |
| 九年级9月考 | 8 | 26 | A~T 二十档 | A(1) | 487 |

四处会让默认配置出错的差异：

1. **「每三列一组」并非普遍成立。** 七八年级表里有「体育」，它在七年级上/下是三列组，
   在**八年级上/下只有一列**（不分分数/排名/等第）——从该列起分组整体错位。
   `保留列数` 必须取**表头最后一个有字的列号**，不能按 `3 × 组数 + 2` 推算。
   （八年级上按公式会算成 35，实际是 36。）

2. **八年级下前两列顺序相反**：`A=姓名, B=学号`，须设 `学号列: 2`。
   不设也能跑完，但会**按姓名分配班级**——人名不是纯数字，全部落进「未分班」。

3. **等级顺序不能按字母排。** 七八年级的等级是 `A+ / A / B+ / B / C+ / C`，
   字母序会排成 `A, A+, B, B+, C, C+`，把 A+ 排到 A 后面（其实 A+ 更好）。
   必须显式写 `等级顺序: ["A+","A","B+","B","C+","C"]`。

4. **科目组成随年级变**：七年级有生物、地理；八年级加了物理；九年级是物历思政化。
   「总分」列在**七年级上不存在**（只有「加体育权重总分」「不加体育权重总分」），
   故该校的 `排名基准科目` 须改成这两个之一。

## 科目识别：扫描式，不是等距

分析脚本用 `scan_subjects()` 找科目组，规则是**「某列有表头文字，且其后两列恰为『排名』『等第』」**。
不要改回 `header[2::3]` 的等距取法——八年级的「体育」只有一个分数列，等距会让其后所有科目错位。

副产品：**没有「排名」「等第」的单列科目（如八年级的体育）会被自动忽略**，
因为等级类图表无法使用它。这是有意的，不是遗漏。

## 总分口径：一律用不含体育的总分

`normalize_total()` 统一各表口径：取「不加体育权重总分」并**改名为「总分」**；
该列存在时，同名的「总分」列作废（七年级下两者相差 93.5 分，八年级上下两者相等）。
九年级没有体育列，「总分」本身就不含体育，原样保留。

各表实际列名：七年级上**没有「总分」**（只有加/不加体育权重两个）；七年级下有「总分」但与不含体育的不同。

## 等级的两套分档口径：等宽 vs 不等宽

两套等级**都按年级排名决定**（与分数无关），但**档位宽度不同**，跨年级比较时必须注意：

| | 九年级 A~T | 七八年级 A+~C |
|---|---|---|
| 档数 | 20 | 6 |
| 各档人数 | **完全相等**，每档 25 人（5.1%） | **相差悬殊**：A+ 10%、A 30%、B+ 25%、B 20%、C+ 10%、C 5% |
| 性质 | 等分位 | 不等宽分位 |

判定方法（脚本已实现在 `renderHeader` 里）：取基准科目各档占比，极差 < 3 个百分点即为等宽。
不等宽时口径说明会改为逐档列出占比，并提示「占比越小的档位越窄，跨档比较时留意」——
否则读者会按等宽去理解，把 A 档 30% 的宽度误当成 A+ 的 10%。

四张七八年级表的占比四次都稳定在 10/30/25/20/10/5（七年级上 A+:57 A:172 B+:144 B:114 C+:58 C:26），
说明这是**固定的分位比例**，不是按分数划线。

## 报告结构（四节）

1. **班级总览** — 总分等级构成与关键指标卡
2. **单科跨班深度对比 · 分数分布与等级构成** — 选定科目后，画各班分数分布的核密度曲线，
   **等级分界以灰色分带画在曲线背后**，带顶标档位字母；悬停同时给出「所在分数段人数」与「所在档位人数」
3. **科目 × 等级 人数热力图** + 下方**各科等级分布曲线**（见下）
4. **明细数据表**

班级选择器默认 **11 班**（热力图与明细表共用同一个默认值）。

### 各科等级分布曲线的做法

要求是「和第二节一样的密度曲线」，但横轴是等级。做法分三步：

1. **在分数轴上做高斯核密度估计**（与第二节完全同一套算法、同一带宽规则），得到分数密度曲线。
2. **重映射到等级坐标**：把每个采样点按分数落在第几档、在该档的分数区间内线性插值，
   换算成连续等级坐标 λ ∈ [0, N-1]（分数越高 λ 越小）。横轴于是是等级，形状仍来自原始分数，
   不同分数尺度的科目才能叠在一张图比。首尾档之外取 0 / N-1，档间空隙取相邻档中点。
3. **λ 空间平滑 + 面积归一化**：重映射把每档的分数区间压缩成 1 个 λ 单位——八年级档宽可达 40 多分，
   压缩比近 10 倍，档内原本平缓的密度起伏被放大成近乎垂直的尖刺（试过，红线上冲 6 倍）。
   这是坐标压缩的产物、不是数据特征，故在 λ 上补一次高斯平滑（σ=0.3），再按曲线下面积归一化。

**不要用「每档取中点值连折线」**：那等效于只用 N 个采样点，用户明确否决过。
**也不要用「每档取区间积分」**：积分会随档宽剧烈起伏（语文 A 档跨 10 分、B 档只有 0.5 分，同样密度下积分差 20 倍）。

y 轴是各科归一化后的密度，**峰高不等于人数占比**，轴标题写「等级密度（各科归一化）」，
浮窗里同时给出实测人数供对照。

三类科目不画进折线（**数据不丢，热力图里仍是全的**，页面会列出未画入的科目及原因）：

1. `体育` —— 按另一套口径计分
2. `加体育权重总分` —— 是含体育的总分，与总分重复
3. **分布退化**的科目 —— 判据 `maxShare > 3/√N`（N 为档数）：20 档时阈值 67%，化学 78% 被剔除；
   6 档时阈值 122%，即不会误剔。**这个阈值必须随档数缩放**——最初写成固定 50%，结果八年级的
   优秀班级（6 档下天然 50%+ 集中在 A 档）被整批误判剔除，只剩 4 科。

总分作灰色虚线基准（与第二节的全年级基准同一处理，不占分类色）。
分类色上限 8 种，科目多于 8 个时只画前 8 科并列出其余的。

图例同时是选择器：悬停/聚焦某一科会淡化其余曲线——线条多时靠这个才看得清。
**高亮必须按对象比对，不能按数组下标**：绘制顺序是「基准先画（压最底层）、学科后画」，
图例顺序是「学科在前、基准在后」，两者不一致，用下标会整体错一位（悬停"语文"实际亮的是"总分"）。

### 第二节的横轴是反的：高分在左

第 2 节的横轴为分数、**自左向右递减**（高分在左），这样 A 档落在左侧，与热力图/明细表的列顺序
（`A B C … T`）一致。用户明确要求过这个方向，不要"顺手改回"常规的递增轴。

实现上只有一处：`const x = v => M.l + (x1 - v) / (x1 - x0) * iw;`（用 `x1 - v` 而非 `v - x0`）。
但**凡依赖「x(小) < x(大)」的地方都要一并改**，否则会翻错：

- 分带的像素范围：必须用 `spanX(lo, hi)` 取 min/max，不能写成 `Math.max(x(left), M.l)`
- 分带的数据矩形：`x: Math.min(x(b.lo), x(b.hi))`，否则矩形会向右溢出到相邻分箱
- 分界分数标签的锚点：用 `Math.min(Math.max(x(b.left), M.l), M.l + iw)` 夹紧

第 3 节的曲线图横轴是**等级**（A 在左），本来就与表格一致，不受影响。

### 档位分数区间必须用稳健区间，不能直接用 min/max

各档在分数轴上的区间若直接用该档的 min/max，会被**单条异常记录**毁掉。九年级数学就有一例：
某学生排名第 5（属 A 档）却只有 79 分，而 A 档其余人都在 91~95。这一条把 A 档的最低分从 91
拉到 79，于是 A 档区间 79~95 与 B 档 86~89 **重叠**；相邻档取中点时算出「左界 85.5 > 右界 84」
的**负宽度**，前端按 `if (xb - xa < 0.6) return` 跳过该带 —— **B 档在图上整个消失，且不报错**。

修法是 `_robust_range()`：两端各去掉 1 个极端值（样本 < 8 时不动，避免把区间削没）。
换数据后如果又出现「某个档位字母不见了」，先查该科该档的分数区间是否与邻档重叠。

构建脚本已加**分带自检**：逐科逐档算一遍宽度，负的会打印警告。这类问题必须靠自检发现，
肉眼在 20 个字母里少一个很难注意到。

### 改这类图表时容易踩的两个坑

- **`Math.max(..., 1)` 这类下限**。原先是百分比量级（0~100）时写的保护值，改成归一化密度（~0.1）后，
  这个下限直接主导纵轴上限，把曲线全压到图底。类似「为了防 0 而写死的下限」在量级变化后都要复查。
- **首尾判断写反**：`k === 0 ? -Infinity : ...` 与 `k === len-1 ? -Infinity : ...` 要分清哪端该外延，
  写反会在 k=0 时访问 `bs[-1]`，抛异常并让**同一函数后面的所有图表一起空白**（明细表也会没）。

原先独立成节的「各班各科等级构成对标」（堆叠条形图）已**并入第 2 节**，不要再单独建——
等级本来就是分数轴上的切点，画在曲线背后比另起一张堆叠图更直观。
`barMode` / `renderPanels` / `renderRampLegend` / `mode-seg` 已随之删除。

### 等级分带的实现要点

分带区间取自**全年级**该科各档的实测分数区间（数据里的 `subjects[科目].b`，每档 `[最低分, 最高分]`）。

**注意方向**：等级数组是**从好到差**（分数从高到低），而分数轴**从左到右由低到高**。
`b` 里的 `[lo, hi]` 是「本档最低分 / 最高分」，**不是**「左边界 / 右边界」。相邻档的分界是
「本档最低分」与「下一档最低分」的中点：

```js
b.left  = (b.lo + bands[k+1].hi) / 2      // 本档靠低分的一侧
b.right = (b.hi + bands[k-1].lo) / 2      // 本档靠高分的一侧
```

把这层关系搞反会让 `right < left`，宽度为负，整条分带被 `if (xb - xa < 0.6) return` 静默跳过
——**图上什么都不显示，也不报错**。这个坑踩过一次。

**首尾两档必须向外延伸到 `±Infinity`**。分带只覆盖全年级的实际分数范围（如总分 50~477.6），
而横轴因留白会伸出这个范围（285~490）。若不外延，477.6 分以上的分数不属于任何档，
`bandAt` 的兜底 `|| bands[bands.length-1]` 会落到**末档**，把最高分报成 T 档。
（首尾边界变成 Infinity 后，画带时的 `Math.max/Math.min` 钳制天然处理它，但**分界分数标签
必须加 `Number.isFinite(b.left)` 判断**，否则界面上会印出 `Infinity`。）

**验证方法**（别靠肉眼读截图）：`--dump-dom` 导出渲染后的 DOM，取出分带字母的 `x` 坐标，
按横轴刻度换算回分数，与各档应有的区间中心比对；再用合成 `PointerEvent` 触发悬停，
比对浮窗报的档位与按分数区间应有的档位。这两项各在 5 个位置跑一遍，比看图可靠得多。

分带用中性灰（`--band` / `--band-edge`），不用等级色阶：背景上彩色会和曲线抢视觉，
也会被误读成多出来的一条数据系列。

档位字母标在带顶；**档数 > 10 时不再标各档分界分数**（九年级 20 档时每档仅约 60px，
数字会和字母挤成一片），分界位置由竖线与横轴表达。

## 分档数随等级数自适应

`make_bands()`：等级 ≥ 8 档时四等分（优秀/良好/中等/待提高，约等于年级排名四分段）；
< 8 档时只分三组（优秀/中等/待提高）。6 档若强行四等分，中间两组会各只剩一档，读不出意义。
九年级 20 档 → 4 档；七八年级 6 档 → 3 档。

页面模板里凡涉及等级的文案（色阶图例、优秀率口径、分档说明）均由数据生成，**不要再写死档位字母**。

## 模板的两个占位符

`页面模板.html` 里有两处占位符，构建脚本逐个替换并各自校验存在性，缺一个就报错：

- `/*__DATA__*/null` → 注入 JSON 数据
- `__EXAM__` → 替换成考试目录名（HTML 转义后），出现在 `<title>` 和页头 `.exam-tag` 标签里

`<title>` 与页头**必须带考试名**：五份报告同时打开时，标题一样就分不清哪份是哪份。
用构建期替换而非 JS 设置，这样标签页在脚本执行前就显示正确标题。

## 写死档位踩过的坑

曾有一处 `d.c.slice(0, 5)` 硬编码「前 5 档 = 优秀」，那是九年级 A~E 的宽度。
换成 6 档的分级后，前 5 档约等于全部，**优秀率全部显示 100%**。
凡按档位下标取值的，一律用 `BANDS[i].from/to`，不要用字面数字。

## 图上分档

分析脚本按等级数**四等分**得到 `优秀/良好/中等/待提高`。只有当各档人数接近（即等级是排名等分档）时，
这个分法才等价于年级排名四分位；否则需在页面文案里说明。

## 配色

班级系列色由分析脚本从 dataviz 参考调色板按顺序取（最多 8 个），浅色/深色各一套，随主题切换。
**同时上色的班级超过 3 个时**，脚本会提示——此时需用 dataviz skill 的
`scripts/validate_palette.js` 跑一遍 `--pairs all` 确认配色仍通过 CVD 与对比度检验。
等级色阶（序数）两端有硬约束：浅色面不浅于 step 250，深色面不深于 step 600。

## 改数据后

用户换新考试数据时：把 xlsx 放进新的考试目录 → 走一遍上面的流程。
数据表更新（同一场考试重出分）时：重跑第 4 步即可，页面会整体刷新。
