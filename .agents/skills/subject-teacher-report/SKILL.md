# 科任老师单科分析文档

给每位科任老师一份只讲他那科的文档：**上次大考**与**本次大考**的该科跨班分数分布与等级构成对比，
外加本次大考的本班该科目标生。每科一份自包含 HTML（内联 CSS/JS，无外部依赖）。

## 产出

```
成绩分析工作区/数据/<本次考试>/科任老师文档/<班级>班-<科目>.html
```

每份三节，**顺序固定**：

1. **本次大考** · 该科 —— 开头一段「考试情况总结」（由分布曲线算出），然后是跨班分布曲线 + 等级构成
2. **本班该科目标生**
3. **上次大考** · 该科 —— 同第 1 节的结构，用该场自己的等级体系

上次大考放最后是用户指定的：科任老师最关心本次，历史对比是背景。

## 前置

该考试目录下必须有 `分班数据/*.csv`（由 `按班拆分成绩.py` 生成）。**不需要读 xlsx**——
每科都有 分数/排名/等第 三列，总分排名也在内，目标生与分布图所需的一切都在 CSV 里。

```powershell
$py = "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe"
cd 成绩分析工作区

& $py 脚本\生成科任老师文档.py 九年级9月考 八年级下 --班级 11   # 生成
& $py 脚本\验证科任文档.py                                    # 验证（真渲染，必跑）
```

参数：`--班级`（默认 11）、`--目标生上限`（默认 100）、`--倍数`（默认 1.3）、`--科目`（默认取两场交集）。
两场考试各自读自己目录下的 `配置.json`（`等级顺序` / `重点班级` 沿用既有机制）。

## 口径（已与用户确认，不要自作主张改）

| 项 | 口径 |
|---|---|
| 目标生 | 年级总排名 ≤ **100**，且该科排名 > 总排名 × **1.3** |
| 排名基数 | **去英才班版**（如九年级 487 人），不是含英才班的 516 人版 |
| 目标生范围 | 每份文档**只列该科**的目标生，不附全科汇总 |
| 科目 | 两场考试的**交集**，减去 `化学`/`总分`/`加体育权重总分` |
| 两次考试的档位差异 | **分章节布置**，各自用自己那场的等级体系，不做跨档对齐 |
| 等级构成 | 每节两块：**该科** + **总分**。该科靠后而总分不靠后，才是真偏科 |
| 本班曲线 | **橙红 `#eb6834` + 线宽 3.2**（其余班级 2）|
| 考试情况总结 | 本次大考一节**开头**，≤ 140 字，由分布曲线算出 |

## 本班：橙红色加粗（主报告同步）

本班固定用调色板第 2 位 `#eb6834`（橙红）并加粗——曲线一多，粗线是不靠颜色也能定位的手段。
**这个色原属 02 班**，现在是「某个班固定占一个槽位」：`assign_colors()` 把本班排在最前取橙红，
其余班级按原顺序取剩下的色（于是 02 班从橙红变绿，01 班仍是蓝）。

- 实现在 `生成分析页面.py` 的 `FEATURED_IDX` / `assign_colors()`，**两个脚本共用**（科任脚本 `G.assign_colors()`）。
- 配置键 `本班`（默认 `"11"`），主报告与科任文档都认。本班不在 `重点班级` 里时不会有橙红曲线，
  主报告会打印提示、科任脚本会自动把本班补进 focus。
- 只改「哪个班用哪个色」，**不动配色集合本身**，所以无需重跑 `validate_palette.js`
  （CVD 与对比度取决于色彩集合，与分配顺序无关）。
- 改动这两个模板时**两个都要改**：主报告 `页面模板.html` 与科任 `科任老师模板.html`
  各有一处 `stroke-width: ... isFeat ? 3.2 : 2`。主报告改完要重跑 5 份报告，不能只跑本次的。

## 考试情况总结（本次大考一节开头，≤140 字）

**默认走人工撰写**，路径：`<本次考试目录>/总结.json`，形如 `{"数学": "……", "_说明": "…"}`。
下划线开头的键当注释，不计入科目。**没有人工版本的科目才用脚本初稿**（`exam_summary()`，注入 `DATA.summary`）。

```
4. 把文字写进 <考试目录>/总结.json
5. 重跑生成脚本 + 验证脚本           → 验证脚本会核对文档里用的是不是人工那一版
```

### 写作要求

- **重形态、轻数字**。用户明确要求「不要罗列太多具体数据，注重整体印象解读」——
  一句话点出整体形态（如「最摊的一条」「头部稳、尾部沉」「中段挤、两头都收不住」），
  比堆四五个分数更有用。每处最多留一两个数字做支撑。
- 判据一律用**两班直接对比**或**无分布假设的间隔**，不用隐含正态假设的阈值：
  报告本身声明「不做任何分布假设」，且实测 4/40 低于 1.5σ 与正态理论值 6.7% 差不多，
  据此说「低分端拖尾长」站不住。
- 低分**孤点**与低分**拖尾**要分开：孤点用「最低分与上一名的间隔 > 0.9σ」判定，不依赖任何假设。
  一个学生 45 分、其余都在 70 分以上，那是孤点不是拖尾。
- 高分端看**前 10% 的门槛**而不是最高分一个人。门槛差 2 分以内当噪声；
  只有门槛也低才说「整体压不上去」，否则说「尖子生没顶出来」。
- 判断**整体位置**用**中位数**，不要用主峰位置（见下）。

### 双峰（`_is_bimodal`）

九年级本次 6 科里，峰检测只在**历史与思政**检出两个峰，正是用户看图认定的那两科：

| 科目 | 两峰 | 谷 | 谷/矮峰 | 峰距 | 中间空档 |
|---|---|---|---|---|---|
| 历史 | 54.2 / 62.6 | 59.1 | 0.964 | 1.18σ | 58~59 分无人 |
| 思政 | 29.5 / 37.7 | 34.8 | 0.982 | 1.27σ | 33~34 分无人 |

判据 = 峰数 ≥2 **且** 峰距 ≥0.7σ **且** 次峰 ≥主峰的 0.6 **且** 谷 < 矮峰的 0.99。
**阈值是实测定的，不是拍脑袋**：最初写「谷 < 矮峰的 0.75」，把这两科全滤掉了——
Silverman 带宽对 n=40 有 3~4 分宽，真实的簇间凹陷被平滑得很浅，看图的凹陷只有 3.6% 和 1.8%。
所以不能按「凹陷有多深」卡，要靠**峰本身的个数与可比性**。

措辞上要落到「两簇在哪、中间空在哪」，而不是空喊「两极分化」。注意中间段**不是无人**——
历史 55~62 分有 13 人，空的只是 58~59 这两分；说「57~60 分这一段无人」是错的。

## 目测会看错（踩过的）

写完总结前必须核对数字，**这几处目测都读反过**：

| 目测结论 | 实测 |
|---|---|
| 语文 11 班在 84~88 分段比 02 班更鼓 | 11 班 3 人、02 班 4 人、01 班 5 人——反而更少 |
| 数学 11 班高分段比 02 班薄 | 85 分以上 11 班 **12 人**、02 班 10 人——反而更多（但前 10% 门槛确实低 3.9 分） |
| 数学/语文 11 班「主峰比 02 班高、重心在上」 | 主峰高 ≠ 重心高：数学主峰高 1.9 分而均分低 1.4 分 |

**教训**：曲线挨在一起时，目测分不出峰位与厚薄；`_peak_at()` 也因此**不能用来判断整体位置**——
主峰位置被偏度带偏，判断整体位置一律用中位数。

关于「倍数」口径的副作用（用户知情后选定）：总排名越靠前门槛越低，年级前 10 的学生几乎必中
（如总排 4 的学生，某科排 22 名即算「落后 5.5 倍」）。结果是候选池可能 100% 命中至少一科。
**这是选定的口径，不要换成「名次差 30 名」或「百分位差」。**

## 数据层：复用，不要复制

`生成科任老师文档.py` 用 `importlib` 导入 `生成分析页面.py`，直接调它的
`read_split_data` / `scan_subjects` / `normalize_total` / `derive_levels` / `summarize` / `make_bands` / `make_ramp`
及调色板常量。**新增脚本一律照此复用**——那边的扫描式科目识别、总分口径、`_robust_range()` 稳健区间
都是踩坑换来的，复制一份迟早两边不一致。

`summarize()` 只传该科一列的列定义即可，但 `levels` 必须用**全场**（所有科目）推导的等级集合，
否则「等级集合外的值」检查会因本科档位不全而误报。

`level_rank_range()` 是唯一复刻的一小段：原脚本把它写在 `main()` 里没独立成函数。

- **默认按总排名由前到后**（名次数字小→大）。
- **拔尖组单独标注**：年级总排名前 `--拔尖线`（默认 **10**）的行用浅琥珀底 + 左侧色条。
  用琥珀而不是班级色/等级色阶里的颜色，避免被误读成数据系列。表头上方有一条图例说明口径与人数。
- **所有 8 列都可点排序**：点一次按该列升序、再点反向，表头带 ▲/▼ 指示；并列时仍按总排名。
  该列定义在 `renderTargets()` 的 `COLS` 里，加列只需往这个数组里加一项。

## 读图说明（曲线图下方）

用户明确要求：**讲统计方式 + 讲怎么读，不要铺陈数轴细节**。三段：

1. 这是**核密度估计**——把每个学生的原始分数当数据点做平滑，不假设正态、不预设分数线，
   所以峰位与胖瘦都是数据本身的样子，均分相同的两个班形态可以完全不同。
2. **看三件事**：峰的位置（越靠左＝高分侧＝主体越强）、峰的胖瘦（越高越窄＝越集中、区分度越低）、
   两侧的尾巴（哪边拖得长哪边人多）。灰色虚线是全年级基准。
3. **一行技术提示**：横轴只画重点班级的分数区间，并点名哪些档位整档在窗外。
   这一行必须留——不说明的话，图上少几个档位字母会被读成缺档。其余（横轴范围、分箱宽、
   落在窗外的具体人数）一律不写。

**容器必须是 `<div>` 不能是 `<p>`**：说明里要放多个段落，`<p>` 不能嵌套 `<p>`，
浏览器会把内层段落提出来，样式全散。`验证科任文档.py` 会检查容器与三项内容是否齐全。

## 陷阱（都踩过）

| 坑 | 实情 |
|---|---|
| **分数列在排名列前一列** | 表头是 `语文,排名,等第`。按「排名列的下一列」取分数会**静默**输出一列名次当分数（已踩过一次，6 份文档的分数全错但格式正常） |
| **自检变量被循环覆盖** | 逐科循环里若只保留最后一科的 info，分带自检就只验了最后一科。必须逐科逐场收集后再统一核对 |
| **档位字母静默消失** | 两种原因，都会让图上少个字母而不报错：① 分带宽度 ≤0.6px —— **整档落在横轴窗口之外**（窗口按重点班分数区间定，最低的几档学生几乎都在 03~10 班，必然出窗）；② 宽度 <13px —— 按设计不标字母（会叠字）。前者**必须在图注点名披露**，否则读者以为缺档 |
| **验证必须给窗口宽度** | 无头浏览器默认窗口 800×600，会把图压窄，13px 阈值以下的档不标字母（正常行为）被误判成缺档。必须 `--window-size=1400,1000` |
| **校验必须分节** | 两节档位体系不同（六档 vs 二十档），档位字母要**按节**取集合。全局取集合会互相顶替（上次的 A 冒充本次的 A） |
| **命令输出别重定向** | PowerShell 里给原生命令加 `2>$null` 会吞掉 stdout（DOM 长度 0）；Python 里用临时文件接 Chrome 输出会因进程句柄未释放导致 `TemporaryDirectory` 清理抛 `PermissionError`。都用管道 |
| **八下的科目列表** | `normalize_total()` 只把「总分」换成「不加体育权重总分」，**「加体育权重总分」仍在列表里**，必须排进排除项 |
| **双峰判据靠峰数，不靠谷深** | 谷深阈值卡不住：Silverman 带宽把 n=40 的真实凹陷平滑到只剩 2%~4%，写「谷<矮峰的 0.75」会把真双峰全滤掉。改用「峰数 + 峰距 + 两峰可比 + 有凹陷」，详见上面的「双峰」一节 |
| **主峰位置 ≠ 整体重心** | 主峰位置被偏度带偏：数学 11 班主峰比 02 班高 1.9 分，均分却低 1.4 分。判断整体位置一律用中位数 |
| **校验脚本别假设章节顺序** | 章节顺序调过一次（上次大考从第 1 节挪到最后），按「prev 到 curr」切片会切出空串，报出「所有档位字母都缺」的全假警报。一律按 id 定位，不按 DOM 先后 |
| **总结字数只数正文** | 字数上限检查要只取正文那个 `<p>`。连标题「本次考试情况总结（考试名 · 科目）」一起数，会平白多出十几个字，把合格的判成超限 |
| **`min()`/`max()` 返回元组** | `max(others, key=lambda t: t[1]["sd"])` 返回的是 `(班级, 特征)` 元组。直接当标量解包会把特征字典当数字用，报 TypeError |
| **数 `<tr>` 要带属性** | 拔尖行渲染成 `<tr class="elite">`，用 `count("<tr>")` 数会漏掉它们（每份文档正好少数了拔尖人数）。一律用 `<tr[ >]` 匹配 |
| **`<p>` 里不能放 `<p>`** | 读图说明要多个段落，容器必须用 `<div>`。写成 `<p class="axis-note">` 浏览器会把内层段落提出来，样式全散且不报错 |

## 验证（必做，不能只看「已生成」）

1. **生成器自检**：每科每场打印档数、人数、该科有档数、等级计数合计、均分、分带宽度、缺排名区间。
   **计数合计必须等于有档人数**；`自检问题数` 必须为 0。
2. **JS 语法**：抽出 `<script>` 跑 `node --check`（语法正确 ≠ 运行时正确，这步只是第一道）。
3. **真渲染**：`验证科任文档.py`，用 Chrome `--dump-dom` 导出渲染后的 DOM（**文本，不是截图**）核对：
   两个 SVG 都画出来、够宽的档位字母一个不少、不该有的字母没有、整档出窗的档位在读图说明里被点名、
   读图说明讲了统计方式与读法且不残留数轴细节、等级构成表行列数（含总分成块）、章节顺序、
   本班曲线是橙红加粗、总结存在且不超 140 字、目标生表行数/姓名/默认排序/拔尖标注/8 列可点。
4. **交互也要验**：排序是点出来的功能，光查 DOM 结构验不到。`check_sort()` 会往文档副本里注入
   一段脚本、**程序化点击「落后名次」列头两次**，再读回两次的排序结果核对升序/反向/不丢行。
4. **地面真值比对**：目标生名单必须与既有的 `九年级9月考\目标生名单-11班.md` 逐条一致
   （语文 5 / 数学 10 / 英语 10 / 思政 10 / 历史 13 / 物理 13，共 19 人）。
   这是现成的回归基准，不一致就是口径漂了。

## 转成图片

```powershell
& $py 脚本\导出图片.py 九年级9月考\科任老师文档    # 该目录每个 html 各出一张
& $py 脚本\导出图片.py 九年级9月考                  # 只处理该目录下的 html，不进子目录
& $py 脚本\导出图片.py 九年级9月考 --缩放 2         # 更清晰，适合打印，文件约大一倍
```

输出与 html **同目录、同名**，扩展名 `.png`（`11班-语文.html` → `11班-语文.png`）。
文档按 1400px 宽设计，`--宽` 一般不用改。

`导出图片.py` **必须分两步**，不能直接 `--screenshot`：

1. **先量高度**：注入一段脚本把 `document.documentElement.scrollHeight` 写进 DOM，
   用 `--dump-dom` 读回来。不量的话，`--screenshot` 只截窗口大小那一块——
   页面比窗口高就被**裁掉**（而且不报错），比窗口矮就留下大片空白。
2. **再按这个高度截图**：`--window-size=1400,<高>` + `--screenshot=`。

两个要点：

- **不能用 shell 重定向接输出**。PowerShell 里给原生命令加 `2>$null` 会把 stdout 一起吞掉
  （本项目踩过，DOM 长度变成 0）。一律用 Python `subprocess` 管道。
- **Chrome 单张位图高度上限约 16384px**，超过会静默截断。脚本会提前拦下并报错——
  真遇到时把文档分节或降低 `--宽`，不要硬截。

脚本顺带回报页面上有几个 `svg`、几张 `table`，并在页面异常空白/体积过小时告警，
所以「已生成」四个字之外还有可核对的东西。本机渲染器：Chrome 在
`C:\Program Files\Google\Chrome\Application\chrome.exe`，Edge 在 `Program Files (x86)`。
